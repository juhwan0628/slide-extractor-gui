# M6 Native All-IDR Design
Date: 2026-10-13
Status: Ready for owner review; implementation not started.

## Goal
Reduce time from video selection followed immediately by Analyze to editable results.
M6 creates a comparable native all-IDR preparation backend. Half selection is M7.
Keep the keyframe-only product and the existing FPS isolation.

## Evidence and limits
E3 compares native all-IDR against alternate-IDR on three 300-second remuxed H.264 clips on Oracle ARM64, one run per mode.
Measured total reductions are 25.8%, 50.9%, 44.2%; these are not shipped-app improvement claims.
SP's six full-only detection events were reviewed by the owner as duplicates.
Other clips remain unreviewed. Detector agreement is not ground-truth recall.

## Architecture decision
Use a separately managed native executable, with Python owning cache lifetime and analysis.
The executable uses libavformat/libavcodec and libavfilter to apply the exact cache_filter generated by slide_core.display.
Direct swscale-to-640 bicubic from the experiment is not the product transform.
An executable isolates native failures and supports existing process cancellation.
Do not introduce PyAV or a second display-transform implementation.

## Initial support boundary
H.264 AVCC, progressive constant-dimension streams, with independently decodable IDR key packets.
Select the SourceRef stream_index, not whichever stream the helper considers best.
Validate every key packet's NAL lengths and IDR status; validate codec configuration and decoded frame metadata.
A non-IDR key packet, malformed configuration, incompatible stream, or unavailable helper makes the native backend unsupported.
Restart the complete preparation through the existing FFmpeg keyframe backend after cleaning the native attempt.
Never silently drop a key packet or merge partial native and fallback results.
Cancellation, source changes, disk/quota failures, and invalid timing remain explicit errors; do not retry them as unsupported.
The existing display policy still rejects unsupported HDR/interlace/dynamic transforms.

## Native protocol
Versioned binary output with a fixed magic/version header.
Each frame record carries stream time_base, decoded display PTS, source keyframe ordinal, output dimensions, and bounded RGB24 payload length.
Do not use packet PTS as a substitute for decoded frame PTS.
Validate monotonic PTS, expected dimensions, complete payload, record count, successful exit and terminal completion.
A zero-frame result or truncated output cannot become a complete cache.
Drain stderr concurrently with bounded retention.

## Product integration
Create native/keyframe_decode.cpp, native/CMakeLists.txt and slide_core/native_keyframes.py.
Modify slide_core/pts.py at the decoder boundary while keeping keyframe_stream's cache ownership contract.
Reuse CacheSession, cache pins, quotas, atomic generation completion, Sample construction and existing JPEG policy.
Reuse source fingerprint validation before and after preparation.
M6 uses all frames, preserves existing Sample/PreparedSamples/JSON semantics and keeps existing FFmpeg preview/export paths.
Native selection is explicit for validation; shipped default activation waits for M9/M10.
Backend identity and transform/protocol version must participate in cache provenance wherever reusable generations are selected.

## Lifecycle
No 120-second total preparation deadline.
Use a 120-second inactivity budget tied to genuine decoder/demux progress; do not let repeated empty heartbeat events conceal a stalled worker.
Cancellation interrupts/reaps the owned process and leaves no committed partial cache.
Clean a failed native generation before fallback; preserve a previously completed valid generation.
Retain bounded queues to prevent large-video memory growth.

## Verification and M6 acceptance
Test-first protocol parsing: truncation, unreasonable dimensions/lengths, invalid version, regressing/missing PTS, failed exit, missing completion.
Real fixture tests: H.264 IDR with B-frames, nonzero origin, multiple video streams, 90/180/270-degree rotation, non-square SAR, BT.601/BT.709 and full/limited range.
Unsupported codec and non-IDR/open-GOP inputs use the complete existing keyframe backend.
Test cancellation, inactivity, source changes, disk/quota failure and native-unavailable behavior.
Compare existing FFmpeg and native all output by exact decoded PTS/time_base, dimensions, RGB bytes before JPEG and detector transitions/pages.
Exact image differences block automatic activation until the cause is resolved; do not invent an arbitrary similarity tolerance.
Run the existing complete suite after integration.
Measure the three existing clips as comparisons, not as claimed speedups over E3.
Mac/Windows installed-app validation remains required before release; Oracle cannot substitute for it.

## Later milestones
M7: alternate-keyframe selection, policy-specific provenance, human content review, sensitivity behavior.
M8: complete keyframe metadata index with on-demand images for skipped frames, editing/cache lifecycle integration.
M9: randomized repeated shipped/native-all/native-half comparisons, clip and full lecture, immediate Analyze, Mac/Windows.
M10: pinned native build dependencies, licensing, artifact audits, clean-machine checks and beta release.
M6 does not expose a half/full UI, remove handwriting duplicates or overlap preparation and detection.

## Self-review
Scope is all-IDR integration only; native output is not allowed to bypass cache or source safety.
Fallback does not imply FPS. Full-keyframe fallback preserves the current supported input contract.
Performance figures and human review scope are explicitly separated.
